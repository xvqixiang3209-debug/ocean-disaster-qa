## 1. 本轮要完成什么

请先只读复审、设计下一阶段可执行方案，交给 Codex 实施。当前重点是第三个功能：**基于客观预报 NC 数据，在用户提问地点的地图上绘制海浪、海面风二维结果，并生成同一地点、时段的数据报告。**

三项产品目标仍是：

1. 灾害与预警知识问答：本地资料、官方网络来源、业务工具共同支持回答，支持连续追问。
2. 相似台风查询：查询历史路径相似案例、来源机构及路径差异，并在地图显示；路径相似不等于灾损相似。
3. 客观预报产品：从真实 NC 计算指定地点、时间的风浪，绘制二维图和过程图，生成浙江或所问地区的未来 72 小时参考报告。

本次不是请求重新设计一个空白项目，也不是让模型凭语言生成示意图。已有的解析、选数、地图、报告和检索体系需要保留。重点找出同类问题的通用缺陷，而非为固定题号写特例。

请先读 [二维地图绘制指南](OBJECTIVE_MAP_RENDERING_GUIDE.md)，再结合本文件和 [验证记录](SNAPSHOT_VALIDATION.md) 审查。

## 3. 必须明确的绘图产品要求

### 3.1 用户实际期望

例如用户问“明天08时朱家尖附近海浪、海面风怎么样？给我二维图”，系统需要：

1. 解析朱家尖和明天08时，选符合该地点、时段和起报约束的真实数据。
2. 程序从 NC 提取对应范围和时次的二维数据，而不是让模型编造数值或用全省平均替代。
3. **现有问答页面的地图移动到朱家尖，叠加当地海浪或风速栅格，显示图例、单位、批次、有效时刻和缺测状态。**
4. 切换海面风时，使用同一范围、时刻的风速底色和 u/v 箭头。一个请求同时要求风浪时，需要清楚表达当前显示哪一要素，以及如何比较另一要素。
5. 文字数值、地图、下载图和报告可以追溯到同一数据集与窗口；连续追问不能丢失上轮地点/日期，也不能继承已被用户纠正的参数。

“提供一张 PNG 下载链接”“只绘制全省图”“回答里说某地点但地图仍停留全省”都不满足这个要求。当前已具备 Canvas 地图叠加，改进时不能退化成上述形式。

### 3.2 单时刻与 72 小时图的区别

- 单时刻图：所有格点属于同一有效时刻；海浪为波高底色，海面风为 `hypot(u,v)` 底色及该时刻风矢量。
- 72 小时逐格最大值：每个格点对窗口内所有原生时次分别归约；各点峰值时刻可不同，不是选一张“最大时刻”的快照。
- 区域峰值时刻快照：先找范围内全时段峰值发生时刻，再绘制该时刻完整场；不能冒充逐格最大图。
- 最大风速必须先逐时计算 `hypot(u[t],v[t])` 再取时间最大值，不能将两个分量各取最大后合成。
- 缺测透明，不按 0 处理；原生网格统计在显示下采样之前完成。最大风速图不绘制拼接的风箭头。

现有下载 PNG 带经纬度坐标轴，但没有底图。若需要导出“带底图的地图图片”，请作为扩展方案说明如何实现；它和现有网页上的地图叠加是两种交付。

### 3.3 数据解释暂不作为打通路线的阻塞

用户已同意先使用 L2/L5，沿用明确标注的临时解释。WAV 暂按有效波高，SSW 的 u10/v10 合成风速暂按阵风口径；来源产品的精确统计间隔、单位和无时区时间解释仍待业务确认。

L2/L5 这些产品没有气压，不能从风速估算气压或混入其他批次数据补齐。MWD 定义和元数据存在疑问，当前不画浪向。后续业务核定时更新解释版本和缓存键，不要求本轮先猜出最终定义。

## 4. Claude 请优先验证的代码问题

下列前三项来自当前静态审查，**不是本轮已经通过真实新问答复现的失败**。请先用合成 NC、接口与前端测试确证，再设计最小修改。

### P1：未登记地点不应静默退回浙江或保留旧地点

- `forecast_runtime/objective_scope.py` 的 `resolve_scope` 在未命中固定地名时默认浙江。
- `marine_kb/objective_context.py` 的追问检测也主要依赖固定地点名。
- 复核：“绘制嵊泗明天08时海浪二维图”“同一时段换成普陀附近”。
- 需要区分未指定地点、已登记地点、未知地点、歧义地点、用户显式 bounds；扩展可配置地名/坐标解析，或明确请求澄清范围。
- 验收：明确问了未知地点时，不能静默拿全省/旧地点的数值和图层作为当地结果。

### P2：首帧缺测海点恢复后的统计与最大图一致性

- `objective.py` 的 `_mask` 主要用源首帧波浪有效点形成 `wave_valid` 掩膜。
- `stats72` 复用该掩膜；`temporal_maximum` 对海浪已允许后续时次恢复的有效点。
- 当前测试已覆盖最大图恢复后续海点，但应补充同一合成场下报告峰值、超阈过程、最大图和快照之间的一致性。
- 反例：某点首帧缺测、后续恢复且出现区域最大值；另一个点始终缺测。不能漏算前者，也不能让后者成为 0。
- 请给出明确的“静态海陆掩膜”和“逐时数据有效性”契约，而非随意让各个统计函数采用不同语义。

### P3：同一请求要求风浪两图时的交付

- `objective_bridge.py` 当前地图动作主要选 `fields[0]`，`map_assistant.js` 接收首动作；现有面板可以切换要素。
- 不能将这描述成风浪已同时叠加或同屏对比。
- 评估保留单图明确切换、双图分屏，或受控图层管理哪种最小改造最合适；先给方案及接口，不破坏当前 `objective_field` / `objective_maximum` 契约。
- 验收：用户明确要求两要素时，回答交付两类数据，界面清楚显示当前要素，切换后范围/批次/时段一致，旧请求不能覆盖新图层。

### P4：地图精度和导出能力的边界

目前用模式波浪有效点作海点掩膜，粗网格可能覆盖部分岛陆；这不是精细岸线裁剪。请区分必须修的数值/范围错误，与精细海陆多边形、带底图导出、双屏等扩展功能。

不能通过增加插值平滑或 AI 生成图片制造岸边精度。若采用边界数据，说明来源、坐标系、版本、缓存及原生统计和显示裁剪各自的处理方式。
