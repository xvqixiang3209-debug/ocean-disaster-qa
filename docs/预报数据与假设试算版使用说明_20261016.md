# 预报数据与假设试算版

## 2026年10月17日涉海活动数据链路更新

当前版本为 `phase1.4.2-data-first-activity`。日期和地点明确的赶海、游泳、海钓问题先执行数据任务：核对授权NC目录，复用或下载已起报批次，按时间和海点实际读取WAV、SSW、OCU、SST、SWL，再查询关联天文潮及官方运营公告。真实数值进入 `data/forecast_runtime/forecast.sqlite3` 的 `grid_point_series` 表，以源文件SHA、变量、位置、时段和解析版本隔离；NC原件继续留存。文件、变量、时间轴登记不冒充已取得某海点数值。

本次朱家尖示例采用122.4°E、29.9°N区域参考海点，不是南沙、东沙浴场精确定位。按10月16日20时起报、覆盖10月17日全天的同一批次提取到WAV 0.4248—0.6553m，SSW 2.5566—7.3721m/s，OCU 0.0526—0.6387m/s，SST 24.0625—24.2510（原单位Celsis D，摄氏解释仍为假设），SWL -1.0654—1.2109m。沈家门参考潮表低潮06:18、19:30，高潮13:03。以上是模式预报与天文潮表，单位、基准和风种继续按既有试算假设标明，不称实况。

运营方10月1日公告覆盖10月8—31日南沙08:00—18:00、东沙05:00—18:00；它只说明景区营业，不证明可以游泳或海钓。官方水质记录中的朱家尖观测日期为9月28日，程序明确标为历史，不用作10月17日水质。当前没有核定的具体浴场、滩涂或钓点准入规则，程序不会自行编一组风浪阈值，低风浪不自动变成活动许可。

连续对话真实验证已通过：先问10月17日朱家尖三项活动，再问“那今天的高潮和低潮分别是几点”，第二轮保留朱家尖地点并查询潮表。276项自动测试及30项子测试通过，包括同文件并发下载、持久数值复用、历史水质排除、地名坐标冲突、跨日公告匹配和混合子问题查询。实测数据及回答保存在 `exports/朱家尖20261017海况解析与实际问答_20261017.json`。该更新验证了活动数据链路，不表示原160题已经全部完成数据和业务正确性验收。

版本：phase1.4.0-forecast-trial；日期：2026年10月16日。

## 打开和使用

启动本地服务后打开对应端口首页，当前新版为 http://127.0.0.1:8769/ ，已有页面按Ctrl+F5刷新。历史台风地图、知识问答、连续追问在同一“海洋灾害知识问答”页面使用；2026年10月19日起，旧 /chat 与 /chat.html 地址自动回到首页。

首页“潮汐与预报”提供三种查询：

1. **天文潮与高低潮时刻**：选择站点、日期及时段，查看潮位曲线和精确高低潮。逐时最大值与日高潮不是同一个采样口径。
2. **海域网格预报**：选择浪高、10米风速、SWL、海温或流速，输入经纬度及查询时段，查看曲线、极值与批次。超出范围、缺测及不完整时段明确显示。
3. **岸段超警试算**：选择浙江全部岸段或一个地区，在地图查看假设口径下的颜色与最高岸段。灰色表示缺数，绿色表示未达到已知阈值；点击岸段可继续提问。颜色和“超警”均为试算，不是官方发布警报。

台风控制区新增“查看实时台风”，绘制接口已有路径、最新记录点及各机构独立预报路径。实线为记录，虚线为预报。“实时台风历史类比”沿用原路径检索服务，输入风速先从假设的m/s换算为旧匹配服务要求的kt。

右侧海洋助手可直接问：

- “坎门站明天几点高潮，潮位多少？” → “那后天呢？”
- “舟山海域未来72小时风速和浪高是多少？” → “它的最大浪高是什么时候？”
- “浙江未来72小时哪些岸段超警？” → “最高的是哪个岸段？”
- “SHENJIAMEN站明天的天文潮和浪高各是多少？”
- “现在有几个台风在活动？最新位置和强度是多少？”
- “当前台风未来预报路径如何？不同机构分别怎么预报？”

每轮由程序查询/计算业务数值，DeepSeek组织语言；资料库和官方网页仍检索，用于补充解释。复合问题分项查询，某一项缺数不抹掉其他项。回答的“查看本次数据、批次及假设口径”链接保留完整结果；模型只展示前几个岸段时，地图和数据记录仍可检查全部结果。

## 当前假设

用户授权先用假设口径打通系统。本次默认设置：

| 项目 | 首次运行假设 |
|---|---|
| SWL | 纯增水，米，与同一时刻天文潮相加 |
| 天文潮 | 原值已为1985基准，默认不再次订正；原值另存 |
| 阈值 | 使用本次SQL，按厘米、1985基准解释 |
| 时间 | 无时区时间采用北京时间；NC仅写initial time时，以文件名批次为基点 |
| 岸段公式 | ax+b作用于参考站天文潮，再叠加当地网格SWL |
| 站点关系 | 39份按DataFile直接匹配，4份采用明确标记的临时别名，其余保留未匹配 |
| 缺少岸段参考站 | 可选80公里内最近可用站近似，标注粗略坐标距离及关联方法 |
| SSW | u10/v10矢量模；结合文件gust描述，按10米阵风试算，不替代平均风 |
| 海域未给坐标 | 部分城市采用明确标记的假设代表点，不称为全海域极值 |

这些设置不意味着原始口径已经核定。数值检查提示部分潮文件订正状态可能不同；SQL站点坐标有整数精度问题；4个岸段的新旧有效阈值不同。相应限制在试算版本保留。MWD的描述和单位存在冲突，尚未当作波向使用；谱峰周期、独立实时观测等缺项不补造。

实际运行配置文件：`data/forecast_runtime/assumptions.json`。程序每次查询固定一份配置快照，修改不会使同一查询中途混用新旧口径。示例：

```json
{
  "swl_kind": "total_water_level",
  "station_tide_overrides": {"KANMEN": "subtract_base85"}
}
```

上例是修改字段示意，不是完整文件：SWL切换为总潮位后直接使用，不再加天文潮；坎门单独设为原值减Base85。支持的订正模式还有raw_already_1985、add_base85。编辑完整配置时保留其他字段。代码只实现明确的1985统一基准及厘米阈值，改为其他基准会要求转换参数，不自动猜换算。配置切换后原始数据不用重导；修改临时站点别名需要重新执行源文件导入以更新关联。

## 数据与更新

已导入83站主表、198岸段、53份潮文件目录、455,520条逐时天文潮与73,350条有效高低潮记录。桐照文件为空，继续显示缺数；-99999按用户确认视为无效，大陈镇黄、橙两级保留为空。没有执行SQL中的DROP或建表语句，也没有改动原知识库。

智能网格首轮登记L2/L5的SWL、WAV、SSW、SST、OCU五类产品共10个唯一原始文件；派生风速和流速按程序计算矢量模。max/min产品未单独替代逐时序列，极值从查询时间窗计算。网格文件和来源副本保存在data/forecast_runtime/，不是文字向量切片。

production_server.py运行时启动后台线程，约每30分钟检查一次目录并同步各要素最新批次；活动台风查询另有10分钟缓存。下载有网络超时、大小上限、临时文件及完整性检查，失败在状态中登记，下个周期重试。凭据仅保存于本地.env，签名URL不展示。关闭后台同步可在配置文件设置sync_enabled=false。

人工同步命令（在app目录执行）：

```powershell
& '..\.venv\Scripts\python.exe' -X utf8 .\tools\setup_forecast_runtime.py --sync
```

每个要素查询选择一个批次，不拼接不同时次。岸段比较选定一个共同SWL批次；新批次某处缺数时不拿旧批次偷偷补齐。总潮位按同时刻序列叠加后取极值，不把天文潮最大值与增水最大值直接相加。过期或尚未起报的批次不参与岸段等级比较；网格查询可以显示归档数据及过期标记。最新台风记录时间与接口取得时间分开。

2026年10月16日的72小时样例中，请求198岸段，可计算173、缺数25。该数量随产品和时段变化；缺数不等于安全。岸段代表点与参考站不等于独立验潮站预报排名。
