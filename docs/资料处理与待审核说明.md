### 原文追溯核验

对快照中全部2777个唯一原始文件重新流式计算SHA256，并核对台账记录的字节数：未发现哈希或大小不一致；全部原始文件仍存在，全部正文切片有定位标记。

## 2. 首期并非把所有格式都切成文字

| 类型 | 本期处理 | 不能据此宣称 |
|---|---|---|
| PDF | 逐物理页提取；质量异常页隔离；可选本地OCR | 所有图片、表格关系和数字都被正确理解 |
| DOCX、可转换的DOC/WPS | 按段落和表格顺序解析，保留标题、表头、行定位 | 转换后的段落号等于原件印刷页码 |
| PPTX | 按幻灯片提取文本框和表格 | 已读取图中的文字、讲者备注或图表含义 |
| TXT/MD/CSV/普通JSON | 保留行、表行或JSON路径定位 | 缺失值、单位或统计范围已经核定 |
| 模式XLSX | 只保存工作表、表头、行数、时间样例等结构摘要 | 数值已进入业务时序查询、超警计算或RAG事实库 |
| GeoJSON | 保存要素属性、几何类型、范围及数据字典待核项 | 已建立权威站点映射、警戒阈值或淹没模型 |

切片采用结构优先与句边界切分，默认目标长度1100字符、重叠120字符。不跨PDF页拼接，不将不确定的模式数字自动改写成事实。本次切片不调用DeepSeek，不产生“模型已完整阅读所有资料”的承诺。

## 3. 880份模式XLSX：必须先确认口径

884份模式文件中880份非空，另外4份空文件均位于 `TY2106_2024072010` 批次，分别是确定性/集合的增水与水位工作簿。

当前非空表只进入结构资料待审区，未进入正文RAG或超警计算。业务方应逐一确认下列字典，可按同一稳定模式版本批量提供，但必须保留版本和适用范围：

1. `surge`、`waterlevel`的物理定义、单位、正负号约定及缺测编码；不能凭数值大小猜厘米或米。
2. 水位/警戒潮位使用的高程基准及转换关系；不同站点、年份的基准可能不同。
3. 文件夹时间代表起报、计算、导出还是回算时间；历史台风代码配2026批次不自动等于2026真实事件。
4. 表内 `05/14:00` 等缺年月的时间如何还原，采用哪个时区、跨月规则及起报/有效时间关系。
5. 集合表代表单成员、集合均值、分位数还是其他汇总；没有成员维度和定义时不能声称已计算概率。
6. 表头中的站名、代表点、岸段名称、代码的来源与版本，以及每个列是否代表同类对象。

确认后再开发受版本约束的结构化入库、查询和程序计算。不能通过“批准正文资料”按钮，将没有正文的数值表变成可信阈值知识。负值、0与“—”也不得自动相互替换。

## 4. GeoJSON：岸段不等于站点

`ZJCoastal2026.json`包含198条岸段要素，其中173条LineString、25条MultiLineString。`cid`可用于该版本要素标识；`CWZ`只有127个不同值，多个岸段共用站名或模型代表点，因此不能把198条要素当作198个独立验潮站。

四色字段目前是原始字符串属性。数据未明确提供阈值单位、高程基准、正式审批依据和生效时间；其中1条要素缺少橙/黄字段。虽然能画出线条，也不能自动进行四色超警判定。

先前对198岸段模式表的名称匹配得到195个候选对应关系，以下3处存在冲突，必须由资料提供方确认：温峤镇、七都街道、磐石镇。该分析只是候选，不是本次已批准、已写入的业务映射。禁止按文件行序或要素位置强行关联，禁止把历史56岸段表的基准直接继承给现有198岸段数据。

## 5. OCR恢复了文字，但不会自动完成审核

本地安装的OCR组合为 `rapidocr_onnxruntime 1.2.3` 与 `pypdfium2 5.14.0`。模型文件在安装包内，PDF图像在本机渲染与识别，没有发送至外部OCR或DeepSeek。新首期工作台启动模块和`.env.example`已默认启用本地OCR；解析模块单独调用而未配置环境时仍默认关闭。OCR只重试文本层为空、乱码或过少的页。

快照中30份PDF已使用本地OCR，恢复294个物理页；这些来源全部需要人工复核。`needs_ocr`来源数量为0不代表所有页都恢复：仍有约200个页级隔离记录，含空白、稀疏、低质量或超过本次页数限制的页；部分有正常文本的历史资料也可能仍保留隔离页提醒。隔离页不作为正文证据。

默认每文件最多30页、120秒；硬时间上限300秒。恢复结果按源文件哈希、物理页码和处理版本缓存。输出保留 `method=local_rapidocr`、平均/最小置信分数、低置信行数和 `requires_human_review=true`，不会自动设置为批准。

### 实际样本核查与已知漏识

海浪标准 `GB/T 19721.2—2017` 的乱码文本经本地OCR恢复7页。对第4、5物理页的7个关键点（蓝、黄、橙近岸范围，红色近岸6.0m与近海14.0m，警报时效24h，可增加48h/72h）与原页图逐项对照，本次样本均找到；这只是7个点的抽查，不是全文准确率测试或规范现行有效性认证。

同一页仍观察到近岸海域定义中的一整行漏识，且第4页有7行置信分数低于0.8。因此特别要核对：漏行、小数点、`≥/≤`、数字范围边界、单位、附注及表格列对应关系。OCR平均分高也不代表没有漏掉关键条件。

“警报时效24h”不能改写成“每24小时更新一次”。标准中近岸与近海范围、热带气旋/温带天气影响条件也不能删掉后只保留一个阈值。

### 本机启用示例

新首期工作台已默认启用。需要明确设定时，在启动工作台的同一个PowerShell窗口中设置，再启动服务；设置为`false`可关闭。这里只是本地解析配置，不要求提供API密钥：

```powershell
$env:MARINE_LOCAL_OCR_ENABLED = 'true'
$env:MARINE_LOCAL_OCR_MAX_PAGES = '30'
$env:MARINE_LOCAL_OCR_TIMEOUT = '120'
```

未安装OCR依赖或超时会明确记录失败，不会悄悄使用云端。已经入库的资料不会因为改变开关就全部自动重做；需要针对相应来源执行明确的重新解析。现有 `tools/maintain_phase1.py ocr` 优先处理 `needs_ocr` 状态，不等于对所有部分缺页PDF已补齐。长文后续页应另行规划受限重试和人工核验，不盲目放宽到无限时、无限页。

## 6. 旧DOC/WPS和Word安全边界

旧文档由本机Word专用实例读取：隐藏运行、禁用宏和打开时外链更新、只读打开原件，转换到独立临时目录或内容哈希缓存。每批最多50个文件，专用进程有时间限制；仅按自身Word进程PID与启动时间校验清理，不结束用户其他Word窗口。

导入时曾发现部分OLE旧DOC/WPS内嵌主题ZIP，普通ZIP识别会误判成DOCX。现已修复为同时检查顶层签名和正文入口，并完成真实DOC/WPS回归；此问题不是原始文件内容丢失。

唯一仍受阻的 `预报相关资料/警报单/0404警报01.doc` 被本机Word信任中心的文件类型策略阻止。**不要关闭信任中心、全局放开旧格式或降级宏安全来绕过。**请由资料方在受信任环境中核查原件后重新导出DOCX或带文本层PDF，作为新版本导入，保留旧件的失败记录和新旧版本关系。

## 7. 标准、草案及历史资料的审核要求

78份初分“标准规范”资料均处于待审核；识别出的7份草案/报批/上报类资料均未批准。正文能被解析，并不能证明该标准现在仍有效。

审核至少记录：正式名称/编号、发布与实施日期、适用地域/层级、当前有效或被替代状态、草案与正式版关系、业务适用条件、资料使用与外发权限。不能把文件名前缀“2026”自动当作标准版本年份，也不能把公报页眉残留年份当作实际统计年度。

当地应急预案和海浪/风暴潮等级属于不同规则：灾害成因、响应主体、地域层级和阈值条件须分别检索；不能将某一四色警报直接换算为所有部门统一响应级别。

OCR或部分页隔离资料批准时，系统要求审核备注以“已逐页核对”开头记录范围和依据；这只是操作提示，不替代真实人工核查，也不是数字签名。草案不能仅修改状态升级为正式文件。没有可用正文的结构资料不能通过正文批准流程放行。

## 8. 历史事件与SID自动关联

后台根据资料文本中的台风名称、年份等信息提出与现有台风库SID的关联。证据明确的高置信匹配可自动接受；同名跨年、多台风同文、时间缺失等情况留给审核。

必须区分：历史台风编号、国际SID、业务方 `typhoon_id`、文件产品编号和资料批次。不要因为文件里出现“今年第9号”或“巴威”就绑定某个年份。综合公报中不同台风应按片段身份处理，不能把整份年度公报全部挂到一个SID上。

当前303条自动接受关联和342条待审核关联均是切片关联数。检查时先查看原文上下文及日期，再批准/拒绝具体“切片—SID”候选；不要只看中文名。历史参考答案必须保留“历史、未审定”的来源标签，不据此宣称当前登陆、当前警报或当日防御部署。

## 9. 后续从可视化页面导入

1. 启动新首期服务，默认浏览器地址为 `http://127.0.0.1:8767/knowledge.html`，也可从首页“专业知识工作台”进入；不是旧版“知识管理”弹窗。若服务端口另设，以实际启动日志为准。
2. 打开“导入与任务”，选择文件或文件夹。界面合并选择后按每批最多100个文件/180MiB自动排队；单PDF上限180MiB，其他文件（含ZIP）界面上限100MiB。后端还有单次请求250MiB、200文件等校验，不建议绕过前端限制。
3. ZIP最多展开4000文件/1.5GiB；拒绝加密ZIP、嵌套ZIP、越界路径、符号链接与异常压缩比。大批资料先解压后分批选择更便于跟踪失败原因。
4. 上传完成后查看后台任务，不把“任务完成”误当“全部资料审核通过”。空文件、受阻文件、OCR质量提醒、结构资料待确认项都要逐条处理。
5. 回到“资料台账”查看来源、原相对路径、切片定位、质量提醒和SID关联。用具体历史案例问题检验召回与出处，而不是只看切片数量。
6. 对标准/OCR资料进行真实复核后填写审核依据；保留未通过、缺页和草案状态。所需材料不存在时，应允许系统回答证据不足。

新工作台暂不实现旧 `.xls` 解析：虽然上传层可接收，解析会明确显示不支持，应由资料方导出为`.xlsx`后导入。旧界面与新工作台的支持范围和限额并不相同。

知识工作台管理API仅允许本机回环访问，并校验会话令牌，不能直接通过改成 `0.0.0.0` 就安全开放给全单位。正式多人使用前需要账号、角色权限、审计身份和受控代理。

## 10. DeepSeek、联网与“专业RAG”能力边界

资料解析、OCR、切片、索引和证据检索都可以本地完成；这是检索增强问答建设，不是本次训练了一个新基础大模型。

当前新工作台默认 `MARINE_EXTERNAL_MODEL_ENABLED=false`、`MARINE_WEB_ENABLED=false`。所有来源外发授权为false；没有授权时，系统可以返回本地证据摘录和引用，不会因为配置了DeepSeek密钥就自动外发全部资料。启用外部模型须同时明确文档权限、业务范围及来源级授权，保密材料不得直接批准外发。

实时接口仍未接入：台风、风暴潮、海浪模式表里的历史文件名和近期日期不能证明今天的实际预警或未来预报。来源不足、标准未审、模式单位未知、网页不可用等情况应明确说明，不能让模型补编数字或省略适用条件。

## 11. 建议的下一步验收顺序

1. 资料方补交4份空XLSX和受信任中心阻止的1份旧DOC转换版本。
2. 业务专家优先审核高频问题涉及的标准、预案及对应OCR页；先形成少量可靠条款，不一键批准所有967项。
3. 逐项确认模式字典、岸段/站点映射和3处名称冲突，然后建设专门的结构化查询工具。
4. 对高频历史台风的SID关联、灾情表格和多来源差异做抽样验收；保留各来源和统计口径，不擅自求平均或合并。
5. 由资料权属负责人决定哪些文本可发送外部模型，再启用DeepSeek精炼；未授权资料保持本地证据回答。
6. 准备分角色、按问题族隔离的专家测试集，分别统计可回答率、来源准确性、数字/单位错误和安全拒答。本文OCR样本检查不能替代该测试集。

本期已提供真实资料接收、解析、索引、审核流程与问答证据基础；尚未完成全部标准的业务审批、所有页图表的人工核验、模式单位/基准确认或实时接口接入。只有这些边界被清楚记录，后续专业问答能力的增长才可验证。
