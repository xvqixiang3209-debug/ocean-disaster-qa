# P0真实录制的离线回放边界

`tools/replay_p0_baseline.py` 在当前P0源码上重放已录制事务，不加载 `server.py`、`config.py`、`model_layer.py` 或 `.env`，不读取生产数据库，不连接运行中的网页服务，也不调用真实模型。网络出口的socket连接和DNS解析由程序阻断。该工具只用于复现原有回答与失败，不是后续修改提示词后的质量评测。

## 输入与核对

- 原始模型、本地检索和公开网页检索依赖来自本机私有cassette，按原始请求完整指纹匹配。并发独立检索采用 `per_key`，同一请求的重复结果仍按录制次序消费。
- 本地检索返回值中的原段、元数据及检索错误保持原值。资料授权按本次另行冻结的授权快照核对原有内容哈希，不把全部资料设为允许。授权快照在运行开始后复制，其原文件mtime早于运行开始；这不等同于独立记录了每一次授权决定。
- 运行源码与 `run_source_snapshot.json` 核对。任何对应源码字节变化都中止回放。
- `qa` 的执行日期从原生成请求的 `date` 恢复；每个候选的适用性判断时间从原评估请求的 `query_as_of` 恢复，再执行原有适用性代码。不复制原判断结果代替计算。
- 回放成功要求所有原始依赖均消费、没有未知请求或网络尝试，最终发布的HTTP状态及回答或错误文本哈希一致。HTTP认证、会话令牌和网页渲染不在该工具的重放范围。

## 本轮发现的v1录制格式问题

`marine_kb/replay.py` 的v1 `_wire` 将字典键排序。字典的值可以完整恢复，但原始插入顺序丢失。部分嵌套元数据直接进入 `json.dumps` 提示词，结果出现“JSON解析后的值相同，提示词字节不同”，严格指纹因此拒绝。

当前回放工具只对原模型请求中出现过、值完全相等且键顺序唯一的字典恢复已记录顺序；它不修改任何值，不给新请求做JSON规范化，不替换为原提示词字符串，也不放宽指纹。键序存在歧义时不猜测，无法匹配时如实报告失败。这是从原请求中重建丢失输入的受限办法；未来录制格式仍需分别处理“请求指纹的稳定序列化”和“响应值的插入顺序保真”。本轮录制期间没有修改被冻结的生产模块。

## 不能据此声称什么

- 成功复现一条错误或不完整回答，只证明问题能够重现，不表示问题已修复。
- 一条真实事务返回503时，不补跑、不生成假答案。回放核对503和实际错误文本。
- cassette不会动态加载SDK异常类。原来的 `APIConnectionError` 等未注册类型由 `RecordedCallError` 恢复，因此由异常类型推导的公开错误码可能不同。报告单独列出差异，不把trace耗时或错误类的一致性包含在成功定义中。
- 离线读取不产生新增API费用；真实录制与离线回放的调用数分别统计。原始请求、模型草稿与网页正文仍留本机 `tmp/replay/`，不上传公开仓库。

## 命令

```powershell
& '..\.venv\Scripts\python.exe' .\tools\replay_p0_baseline.py --run-dir .\tmp\replay\p0_20261020_005001_b167cdca
```

默认要求该目录计划中的全部事务结果已经生成；可使用 `--case-id M1` 检查一个已经完成的事务。未完成的录制不能冒充完整回放。结果以只含安全诊断的JSON保存在同一私有目录。
