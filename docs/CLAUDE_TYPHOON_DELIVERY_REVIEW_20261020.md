# Claude 复审：台风查询时间与业务字段完整交付

本轮继续沿用 P0–P6 的 DeepSeek、CRAG、本地资料与官方联网检索体系，修复台风接口已经返回数据、最终回答仍漏掉数量或误报缺项的问题。本文是新的专项复审入口，补充 [P1–P6 原复审文档](CLAUDE_FOLLOWUP_20261020.md)，不替代其中尚待评审的归纳证明和跨阶段审查机制。

代码仓库：[ocean-disaster-qa](https://github.com/xvqixiang3209-debug/ocean-disaster-qa)。本轮修改前的公开基线为 `6777f925fd2d4d2c747f3b65e4055ca4ce2eded0`；本轮版本为 `phase1.8.5-typhoon-time-delivery`，最终代码以本文所在提交及交付清单为准。旧文档的行号不能直接套用到新版本。

## 一、问题与本轮结果边界

用户询问“截至今天有几个台风在活动，位置、强度和移动方向是什么”。旧回答只保留“该数量是接口活动列表数量”的说明，未明确交付数字，又读到前一日的历史位置。它还把台风计数套进地点、物理量单位和有效时段的通用模板，给出已有数据仍未取得的缺项。

沿调用链检查，本轮处理了四个层面的原因：

1. 今日查询先生成一个当前时间，后续又读取稍后的当前时间，两次读取之间的微小差异使它被误判成历史查询。
2. 工具结果与最终语言答案之间缺少稳定的字段交付约束。模型或后续恢复删掉数量后，单独的统计口径说明仍可能留下。
3. 计数、台风中心记录、物理格网数值共用过宽的完整性模板，实际应分别核对统计范围、对象坐标和物理量单位。
4. 多子问中的“快照取得时间”“位置记录时间”被误分为定义或中心位置；“台风有几个、分别叫什么”未被工具字段识别器正确解析，回退成位置、强度、方向的默认字段，污染其他子问。

本轮没有把 NC 当成活动台风清单。活动数量、名称、中心位置、强度和移动方向来自台风接口；指定海域、日期的风、浪、流、水位等问题继续走相应的 NC 和其他业务数据查询链路。时间路由的修复也不意味着 NC 变量定义、单位与高程基准已经取得业务方确认。

## 二、修改实现

### 2.1 一次请求使用固定时间基准

入口为 [forecast_runtime/service.py](../forecast_runtime/service.py) 的 `snapshot_query`、`query_time_context`、`as_of_cutoff` 和台风查询流程。一次请求固定当前时刻，今日、历史和未来分支使用同一参考值，避免重复读取时钟造成分支漂移。

今日日期默认按本次执行时刻查询，历史日期或明确截止时刻按对应边界选择已保存接口记录；未来截止时刻不能伪装成已发生的实时观测。回复区分查询截止时间、接口取得时间和中心记录时间，不以下载或查询时间替代观测发生时间。

历史列表是否完整另行核对。个别台风归档记录不能证明当时全部活动台风数量；取得完整历史快照时也保留其快照范围，不把快照外的后续状态视作已知。

### 2.2 从工具输出形成类型明确、可逐项交付的事实

入口为 [forecast_runtime/answer_facts.py](../forecast_runtime/answer_facts.py) 的 `typhoon_requested_fields`、`typhoon_delivery_facts`、`typhoon_fact_text` 和 `fact_text`。

字段识别覆盖前置和后置问法，例如“几个台风”“台风有几个”“分别叫什么”，并独立识别查询、取得和记录时间。计数与具名台风筛选分开：所选记录数不能替代活动列表总数。

工具事实携带 `kind`、`field`、`source_field`、`value`、`status`、范围与时间信息。计数的完整范围、0 个、未知、部分历史列表和陈旧数据分别表达。缺失字段不按 0 处理；中心气压不能填最大风速的交付槽位。

每条 `fact_text` 保留值、对象、时间与范围的对应关系，作为可从原始业务证据中精确定位的正文，而非让模型重新猜测工具内部结构。

### 2.3 源码生成的工具字段建立独立信任边界

入口为 [marine_kb/protected_tool_delivery.py](../marine_kb/protected_tool_delivery.py)：

- `verified_tool_atoms`：验证业务证据身份、正文哈希、原文精确片段和引用位置，再形成受保护的工具原子。
- `_owners`、`_identity_scope_matches`、`_time_scope_matches`：按请求字段、台风身份与日期约束分配子问，不把同一工具的所有字段送进每个子问。
- `merge_tool_atoms`：以同源工具字段替换重复或冲突的模型数据表述，保留其他有依据的说明。
- `resolve_tool_gaps`：只解决与已交付字段直接矛盾的可用性缺项；单位定义、基准、许可、因果和未来预报等缺项继续保留。
- `tool_data_card`：集中展示同一次查询中的数据与时刻，减少重复打印身份、时刻和说明。

[marine_kb/answer_pipeline.py](../marine_kb/answer_pipeline.py) 在处理模型原子时剔除其自行输出的信任标记，工具原子只从经过上述验证的服务端记录注入。`tool_fact_hash` 用于发现后续变化；哈希本身不能代替服务端来源验证。

请重点审查这条边界是否在首稿、局部恢复、最终合并和缺项清理阶段始终成立，不能只检查某个函数的正向示例。

### 2.4 不同业务对象使用不同交付契约

入口为 [marine_kb/facet_contract.py](../marine_kb/facet_contract.py) 的 `delivery_shape`、`_requested_time_fields` 和 `build_contract`，以及 [marine_kb/facet_delivery.py](../marine_kb/facet_delivery.py) 的 `_count_rows`、`_storm_fields`、`_record_clock_fields`、`covered_outputs`、`evaluate_delivery`。

| 问题类型 | 本轮核对的交付内容 | 不能代替它的内容 |
|---|---|---|
| 活动列表计数 | 明确数字、统计对象及范围、统计截止时间、来源 | “该数量……”说明、风速、个别台风记录数 |
| 数量及名称 | 计数内容及台风名称或编号 | 只有总数、无名称的泛称 |
| 台风中心位置 | 对象身份、经纬度、记录时效、来源 | 行政区名称、接口下载时刻 |
| 强度与相关数值 | 按问题分别核对强度、最大风速、风力、气压 | 用气压替代风速、缺失值填 0 |
| 移动信息 | 按问题分别核对方向与速度 | 只给速度却认为方向已答 |
| 查询与记录元数据 | `query_time`、`snapshot_time`、`record_time` 分别对应原字段 | 三种时间互相替代、误判成概念定义 |
| NC 或测站物理数值 | 数值、单位、地点或对象、有效时间、来源 | 台风中心记录、跨站拼接的完整元组 |

陈旧记录的身份、坐标、强度和方向仍是已取得的历史值，不再全部改写为缺失；若用户要求目标时点最新状态而没有足够更新记录，只保留时点适用性不足，整题仍可为 `partial`。询问旧记录的记录时间本身可以完整交付，不要求它变成新实况。

明确验证的空活动列表可以回答“0 个”，并说明没有可列示的活动台风中心等字段。接口失败或部分列表不能走这个分支。

### 2.5 多余缺项只在明确边界内移除

[marine_kb/scope_gate.py](../marine_kb/scope_gate.py) 只对独立、且该类型契约明确不需要的物理计量单位或行政地点缺项做范围清理。计数的统计范围、有效时间、原始出处，以及物理数值的单位和基准继续保护。

物理数值行只缺地点时，保留已存在的数值、单位、时间和来源；完整性仍不足。不同站点的时间与数值不能拼成一个完整记录。一个缺项被移除，不代表该子问自动变成完整回答。

### 2.6 录制后增加的最终展示修复

最后一轮稳定录制仍发现一条具体反例：模型生成的四列表格行 `c3a1` 只陈述中心风速，却继承父级对象“风速”并被 grounding 绑定到六个子问。合并工具事实时仅清理了风速子问的绑定，其他五个绑定继续使这一行重复出现在数量、气压、方向、速度和时间等子问下。

本轮随后增加 [protected_tool_delivery.py 的 `tool_display_atoms`](../marine_kb/protected_tool_delivery.py)。它仅在最终展示边界处理可精确匹配的四列表格行：必须与已验证工具记录的来源、对象、数值、单位、记录时间和限制相符；这些行由工具数据卡展示一次。来源、对象、时间或数值不同的行，以及多台风来源中无法确认对象的行均保留。合法共享解释只展示一次，其完整原子归属仍保留在 grounding 和完整性审计中。

这项修改没有改变 grounding、恢复提示词、模型生成调用或覆盖判定。因此它修复的是重复展示，**父级对象继承和错误多子问归属的源头仍需 Claude 继续审查**。最终三次真实问答属于增加展示修复之前的稳定代码；展示修复使用该次真实录制的 `c3a1` 做离线阶段回归，不能把它描述成补丁后重新生成的端到端模型回答。

## 四、请 Claude 继续审查的问题

### 4.1 交付字段与语言判断发生冲突时如何收敛

本轮保证来源验证通过的工具字段进入其所属子问，但通用覆盖审查、逐句 grounding 和后续恢复仍可能给出相互矛盾的意见，最终维持 `partial`，甚至过度保守地隐藏已经有据的核心说明。

请沿真实代码分析：哪些判断属于可由程序复核的字段完整性，哪些属于仍需证据归纳的结论；意见冲突能否定向落到单个事实或关系，以有限次数复核解决，而非整段重写、全局删句或放宽所有校验。请提供明确的数据结构、调用阶段、保留和拒绝条件，以及反例测试。

另请优先分析 2.6 的归属源头：为什么“风速”从父问题继承后，会使同一表格行归入数量、气压、方向、速度和记录时间子问？工具字段归属修复与普通模型原子归属之间仍存在差异。请给出通用的子问对象、谓词、时间角色约束，以及有意共享解释和错误多归属之间的程序边界；不能只扩大最终展示去重正则。

### 4.2 防止新保护机制扩大成无条件发布通道

请检查伪造信任字段、来源哈希或原文偏移变化、错误日期、其他台风身份、部分列表、缓存陈旧、未来时点，以及不完整多台风记录能否被错误接纳。尤其检查：

- 受保护字段只能证明原始记录内容，不能证明未来趋势、因果归属、官方预警或公众活动许可。
- 部分列表不能证明完整总数；完整空列表与取数失败不能混同。
- 有旧记录不等于有目标时刻最新状态；缺新状态也不等于旧值和旧记录时间均未取得。
- 单字段满足不等于多台风、多对象全部交付，数量、名称与每个对象的字段仍需对应。
- 模型侧分类错误不能改变服务端来源验证和子问范围约束。

### 4.3 向更多业务问题类型外推

本轮以台风动态暴露的缺陷为切入点，目标不是固定三道题。请评估相同的“已验证工具字段—不可变子问—最终交付”链路如何推广到预警清单、NC 点位与岸段数值、历史灾害对比等类型。

请区分可共用的接口约束与业务专用规则。例如，预警需要覆盖地区、等级和有效期；潮位需要单位、基准和同一地点时间的对应关系；历史比较需要同指标与统计范围，不能只复用台风计数模板。请给出最小的类型扩展方案及跨类型负例，避免把所有数据压进一个大正则或一套统一数值模板。

### 4.4 原 P1–P6 未解决项继续独立记录

原复审文档中的归纳证明、跨阶段审查争议，以及旧离线记录中的 22 条缺证明字段和 17 次正文哈希未匹配，是早先诊断结果。本轮专项没有承诺清除这些记录，也没有把它们重新测成新的通过率。

请先判断需要哪些公开源码和既有脱敏证据即可确认；需要原始私有录制或新模型输出的部分单独列出。不能把本轮路由与字段交付通过，推论为通用归纳能力、所有 160 题或其代表的问题类型均已完成验收。
