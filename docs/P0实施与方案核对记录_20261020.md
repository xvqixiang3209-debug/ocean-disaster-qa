# P0实施与Claude方案核对记录

本轮按 `a6113ee` 对应方案核查并实现 P0 的可观测性与离线回放基础。回答决策规则保持原样，尚未执行 P1–P6，也没有把 G3 的残片问题标为已修复。原始方案存放在 `NEXT_PHASE_PLAN_FOR_CODEX.md`。

## 核对结论

- G3 的恢复记录确实把11条陈述缩到1条，两个判为 limitation 的陈述实际未保留；原记录没有清楚说明每轮触发原因。P0结构回放仍产生相同残片，用于证明观察代码没有暗中改变答案。
- 原稿中部分陈述仍可能错引。不能把“被删掉”直接等同于“原稿正确”，尤其H4所涉及的办理系统和发文机关归因。
- M1 原答仍保留了“鼠类和蚊虫”联合主语。更准确的风险是在蚊媒问题的回答语境中混写鼠媒病，不能断言原文主语在字面上已经丢失。
- 未核现行的国家预案可以按该版本解释，但不能因此认定是当地当前有效的办理依据。
- 后续不能仅因标题含“与”就判科普，也不能仅凭实体/数字都出现在材料里就接受综合结论；还要核对关系、条件、否定和量词。
- 预报起报/发布时间须不晚于查询截止时刻；预报有效时间可以晚于截止时刻，只要处在该批次覆盖范围内。
- “12题专项+4题各追加3次”为24次完整问答。原方案“约15×3/45次”的算术不一致，收费执行范围需明确。

## 已实现

| 文件 | 内容 |
|---|---|
| `marine_kb/answer_trace.py` | `MARINE_TRACE` 默认关闭；请求隔离，记录每次模型调用的阶段、尝试序号、耗时、请求/响应哈希、提供方真实usage及安全错误码；缺usage时保留null |
| `model_layer.py` | 可选 `return_usage`，默认接口不变；不因获取usage失败再次请求模型 |
| `marine_kb/qa_observability.py` | 追踪适配、HTTP/直接问答上下文、线程上下文传播、受限公开事件 |
| `marine_kb/qa.py` | 记录生成/覆盖审查历史、验证错误、恢复后补全错误；生成、覆盖、逐句核对各自实际证据视图的段落哈希 |
| `marine_kb/claim_grounding.py` | 可选审计每条陈述的 retained/drop_rule；限制语未保留的真实原因可见；全部被删时仍有审计事件 |
| `marine_kb/crag.py` | 候选及选中段落哈希、来源重编号与纠错阶段标识；线程传播保持请求隔离 |
| `marine_kb/chat_api.py` | 追踪覆盖标准化到回答的完整HTTP事务；失败响应也可带安全trace；状态接口纳入新增源码哈希 |
| `typhoon/web_reader.py`、`marine_kb/web_supplement.py` | 读取失败保存已知HTTP状态与最终URL；没有响应时为null，不猜状态码 |
| `marine_kb/replay.py`、`tools/replay/` | 显式本机录制、严格指纹/顺序/完整性回放；模型、网页、搜索及通用依赖；未知请求不联网补齐 |
| `tools/record_p0_baseline.py` | 默认只列24次或12次清单；只有显式执行和允许本机私有录制时才装配模型；使用独立Flask测试客户端，不连接运行中的生产HTTP服务 |

公开trace保留结构、哈希和已注册错误码，不输出提示词或资料原文；记录有数量/深度上限并报告截断。原始cassette只放本机 `tmp/replay/`，由 `.gitignore` 排除。

两条G3限制语的审计原因分别为 `limitation_has_citation` 与 `limitation_vocab_miss`。本阶段仅揭示这些规则，尚未放宽规则。

## 使用和验证

修改前在本机重跑为1031项测试及102项子测试通过。P0接入后最终全量回归为 **1094项测试、102项子测试通过**（10.82秒），新增测试覆盖隐私边界、并发隔离、usage兼容、严格回放、HTTP标准化追踪及付费运行器的默认空跑行为。未运行真实模型质量评测。

在应用目录预览付费运行清单，命令不会调用模型、网页或生产服务：

```powershell
& '..\.venv\Scripts\python.exe' .\tools\record_p0_baseline.py
```

取得相应范围的明确授权后，24次运行命令为：

```powershell
& '..\.venv\Scripts\python.exe' .\tools\record_p0_baseline.py --scope 24 --run --record-private
```

每个问题可能有多次模型请求；次数与真实token用量分别报告。运行不会自动扩成45次，也不会自动开展新版160题测试。

程序测试以mock和临时fixture为主，拦截网络验证离线行为；它们不是新的业务正确率。已有G3最终答案和不完整trace不能倒推出不存在的真实cassette。若下一阶段修改了提示词，严格指纹会拒绝旧录制，不能把旧模型输出称为新提示词的真实效果。
